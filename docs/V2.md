# AnalizadorRostroUNOQ v2 — cambios y benchmark

V2 es un proyecto **separado** de V1. No comparte carpeta, servicio ni puerto:

| | V1 | V2 |
|---|---|---|
| Carpeta | `/home/arduino/AnalizadorRostroUNOQ` | `/home/arduino/AnalizadorRostroUNOQ-v2` |
| Servicio | `unoq-app` | `unoq-app-v2` |
| Puerto | `8000` | `8001` |
| Detector | Haar | YuNet + fallback Haar |
| Detección/clasificación | juntas, cada `INFER_EVERY_N` | separadas; detección cada `DETECT_EVERY_N` |
| Tracker | no | IoU entre detecciones |
| Métricas | no | `timings` en `/api/status` |

## Qué cambió

1. **YuNet** (`cv2.FaceDetectorYN`) reemplaza a Haar como detector principal.
   Es más preciso y tolera mejor rostros grandes o descentrados. Si el modelo
   no existe, `DETECTOR_BACKEND=auto` cae a Haar.
2. **Detección y clasificación separadas.** El detector corre cada
   `DETECT_EVERY_N` frames; la red UTKFace corre cada `INFER_EVERY_N`.
3. **Tracker IoU.** Conserva cajas y predicciones entre detecciones para que el
   overlay no parpadee y para no repetir la red en cada frame.
4. **Detección sobre frame reducido.** YuNet recibe un frame de
   `YUNET_INPUT_WIDTH` (320 por defecto), no el frame completo.
5. **Timings.** `/api/status` expone `read_ms`, `detect_ms`, `infer_ms`,
   `encode_ms` y `loop_ms`; la UI los muestra en una línea discreta.
6. **Puerto y servicio propios.** V2 usa `8001` y `unoq-app-v2`; no toca V1.

## Configuración nueva

```dotenv
DETECTOR_BACKEND=auto
YUNET_MODEL=models/face_detection_yunet_2023mar.onnx
YUNET_SCORE_THRESHOLD=0.6
YUNET_NMS_THRESHOLD=0.3
YUNET_INPUT_WIDTH=320
DETECT_EVERY_N=2
INFER_EVERY_N=5
TRACK_IOU_THRESHOLD=0.3
TRACK_MAX_MISSES=2
```

## Benchmark preliminar

No es un benchmark controlado: se usó la misma imagen UTKFace en un stream
MJPEG sintético y, después, el stream real de IP Webcam.

| Escenario | Resultado |
|---|---|
| V2, stream sintético 640×480, YuNet 320 px | **21.2 fps**, 1 rostro detectado, detección 24–40 ms, clasificación ~99 ms |
| V1, mismo stream sintético 640×480 | **7.5 fps**, 0 rostros (Haar no detectó ese recorte) |
| V2, IP Webcam real 1920×1080 → 640×360 | **14.4 fps**, detección ~87 ms, JPEG ~4.8 ms, sin rostro en cuadro |

La diferencia del benchmark sintético no es solo el lenguaje ni el detector:
Haar falló en ese recorte y V1 quedó haciendo detección+clasificación en el
mismo ciclo. YuNet detectó el rostro y V2 separó los ciclos.

Con IP Webcam, el cuello de botella es el **stream de 1920×1080** que la placa
decodifica para luego reducirlo a 640×360. Si el teléfono puede configurarse en
**640×480**, el FPS y la latencia mejoran sin tocar código.

## Ajustes rápidos si se necesita más velocidad

- Bajar `YUNET_INPUT_WIDTH` a `256` o `224`.
- Subir `DETECT_EVERY_N` a `3` (más latencia para rostros nuevos, menos CPU).
- Subir `INFER_EVERY_N` a `8` (la edad/género se actualiza menos seguido).
- Configurar IP Webcam en 640×480 y 15 fps.
- Bajar `WIDTH`/`HEIGHT` a 480×360 si la escena no necesita más detalle.

## Aislamiento de V1

V1 no se modificó: sigue en su carpeta, con su `.venv`, su `.env`, su servicio
`unoq-app` y su puerto 8000. Para comparar, arrancá uno u otro; ambos pueden
convivir porque V2 usa 8001.

## Estado verificado (2026-11-02)

- **V2 activo** en `http://192.168.10.75:8001` (`unoq-app-v2.service`, `active`).
- **V1 detenido** en el puerto 8000 (`unoq-app.service`, `inactive`), sin cambios

## Modelo

V2 usa el mismo `models/utkface_mobilenetv2.onnx` que V1. La precisión de
género/edad no cambia; lo que cambia es la detección y el pipeline. YuNet se
distribuye con licencia MIT (`models/YUNET_LICENSE`).
